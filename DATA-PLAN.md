## Long-term data behavior
- **Refresh policy**: server actions serve a DB cache snapshot first and refetch when stale (category news 45 min, per-feed items 60 min, overseas 60 min; the 20-min hot-list TTL was retired with the hot lists on 2026-11-21); a visible 刷新 button forces refetch; every surface renders its `as_of` fetch time. Daily cron (per refresh triggers) calls `refreshAll` to warm all caches. First load is populated by the same `refreshAll` action via post-submit. Cron schedule: daily 08:02 Asia/Shanghai (stored as 08:02:46 @user.current).
- **Growth**: cache rows keyed by source/category/feed, replaced on each refresh (one snapshot row per key), so the table stays bounded; user data (subscriptions, bookmarks) grows only by explicit user action.
- **Ordering**: hot lists keep source rank order; news and feed items sort by published time, newest first.
- **Time semantics**: published times are the source's own pubDate instants, rendered viewer-local as relative time; `as_of` is the fetch instant.

Imagery not needed: a text-first broadsheet news page — headlines, rankings and source names carry it; no article photos are hotlinked (RSS thumbnails are inconsistent and often expiring CDN URLs), and no decorative imagery serves the reading workflow.

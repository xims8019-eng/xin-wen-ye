# 摘要生成逻辑说明

对应代码：`server/src/actions.ts` 的 `parseFeed`、`loadLearning`、`loadJiangxi`、`loadOverseas`、`getItemDetail`、`getDailyDigest`。迁到自有环境时，抓取和解析部分可原样保留，只有用到大模型的地方需要换成你自己的模型调用（共 4 处：新闻详情要点、学习整理、江西整理、海外整理；每次调用超时上限 110 秒，详情为 60 秒）。

## 1. RSS / Atom 解析（不需要模型、不需要密钥）

- 用正则切出每个 `<item>` / `<entry>`，取 `title`、`link`、`pubDate` / `published` / `updated` / `dc:date`、`description` / `summary` / `content`、`source`。
- 摘要处理：去 HTML 标签、解 HTML 实体、合并空白，截断到 220 字。
- Google 新闻的标题尾部带 ` - <媒体名>`，解析时剥掉，媒体名单独放在来源字段。
- Bing 新闻的点击链接在解析时就解出发布方直达地址（见 `docs/link-resolution.md`）。
- Google 新闻的占位文字（「在 Google 新闻上查看更多头条新闻和观点」及英文同义句）不是摘要：解析时从描述里剥掉（`GN_PLACEHOLDER_RE`），剥完没有实质内容的条目按「仅有标题」处理。

## 2. 「仅有标题」的判定（不猜正文的核心规则）

满足任一条件就标为仅有标题，页面显示「仅有标题」徽标，不生成任何要点：

- 摘要为空；
- 摘要和标题完全相同，或和来源名完全相同；
- 摘要以标题开头、去掉标题后剩下的部分为空、等于来源名或不超过 8 个字；
- 摘要剥掉 Google 新闻占位文字后为空。

分类条目如果有已验证的直达地址但源里没有摘要，入库时会打开文章页取它自己的 meta 描述当真实摘要（`fetchArticleMeta`，带乱码防护）；仍取不到的才保持仅有标题。

## 3. 新闻详情展开（`getItemDetail`，用到模型）

- 入参是这一条的标题和它自己的公开 RSS 摘要。摘要为空或等于标题时，直接返回 `titleOnly: true`，不调用模型。
- 展开前先把链接解析到直达地址（Google 新闻中转 / MSN 转载），并检查是否命中「中国境内打不开」域名名单（命中则返回 blockedReason，页面只展示中文摘要和「复制标题」）。
- 有摘要时，把「标题 + 摘要（最多 800 字）」交给模型，只允许依据摘要本身产出：一句中文概括 `introZh`，加 2–3 条中文要点 `points`。提示词里明确写了不要补充摘要里没有的信息、不要根据标题猜正文。
- 模型不可用时降级：直接把来源自己的摘要原文当作要点展示，不编造。
- 结果按原文链接的哈希缓存（缓存键 `detail:v4:<hash>`），同一条不会重复调用模型。需要登录/订阅的来源（纽约时报、华尔街日报、金融时报、经济学人、彭博、财新等，按标题/来源关键词判定）会标出「该来源可能需要登录/订阅」。

## 4. 学习栏目整理（`loadLearning`，用到模型）

流程：

1. 并行抓 13 个学习数据源（6 个机构直达源 + 7 个 Bing 资讯搜索源），去掉抓失败的源（失败不报错、不填假数据）；搜索类条目超过 45 天的丢弃。
2. 入库前解析链接：Bing 点击链接已在解析时解直达；残留的 Google 新闻中转走 batchexecute 解码，解不出的条目丢弃、不入库；MSN 转载解析到原发布方，解不出的丢弃。报名类条目还要确认官方入口 `officialUrl`（文章页里的主办方链接 > 机构域名 > 机构直达源）。
3. 联合国新闻的中英配对：同一报道的英文和中文链接里有相同的 story id，配上后给英文条目加中文版链接，并去掉重复的中文条目。
4. 按链接去重、按发布时间从新到旧排，取前 40 条候选。
5. 只把「新条目」和「已存但中文摘要仍缺失的条目」送模型，每批 5 条；失败的批次拆成两半重试，再失败拆到单条。每条产出：是否保留 `keep`（过滤娱乐八卦、软文和与学习无关的行政新闻）、三类分类 `category`、一句中文 `summaryZh`（适合谁 + 能学到什么）、2–3 条中文要点 `pointsZh`、适用学段 `audienceStage`、截止日期 `deadline`（格式 YYYY-MM-DD）、费用 `fee`、是否需要报名 `needsApplication`。
6. 整理结果按条目链接持久化（`learning:enrich:v2`，上限 200 条），每次加载都重新套用，旧结果不会被后来的部分失败冲掉；一轮整理出 0 条时不覆盖已有缓存。

学习栏目的硬规则，写在提示词里，迁移时不要删：

- 学段、截止日期、费用只有在标题或摘要明确写出时才填，截止日期必须是具体日期，只写「即将截止」的一律填空。
- 条目标注「无摘要，仅有标题」时，`summaryZh` 必须留空、要点留空数组，绝不根据标题猜测正文（但标题本身明写的学段/截止日期可以保留）。
- 模型分批失败时，那一批条目保留原始摘要并如实标记，不丢条目、也不编造学段和截止日期。
- 全部批次都失败时，整栏降级为按来源提示分类 + 原始摘要展示。

「可报名」列表的门槛在 `getLearning` 接口里：deadline 在今天（Asia/Shanghai）起 30 天内 **且** `officialUrl` 已确认，两条都满足才进列表；课程/资源类不受影响。

**2026-11-22 新增：只留「现在还能行动」的严格门槛（`isLearningNotActionable`）。** `getLearning` 返回前对每条重新套用（代码规则 + 已存的模型 keep 判定），命中任一就不出现在列表里：截止日期已过；已结束的活动报道（研讨会/研讨活动且无开放报名或回放、收官、获奖名单、圆满结束等）；面向中小学/初中/高中学生或博士/硕士研究生的内容；纯新闻、论坛、行业动态；只面向其他国家本国学生/居民的机会（如仅限巴基斯坦、马来西亚学生）；入学时间已过的招生。首页「本周学习」和「近期可申请」同样受此约束。筛完条数可以很少，不拿新闻凑数。

## 5. 江西专升本整理（`loadJiangxi`，用到模型）

- 4 条 Bing 搜索（无时间窗，往年材料作备考参考），标题含成人高考/自考的过滤掉。
- **2026-11-22 新增入库过滤（`isJiangxiHiddenNoise`）**：培训机构营销（机构评测/测评、十大机构、哪家好、选机构、排行榜类）和高考择校文章（面向高考生选大专，含 gaokao.eol.cn 及一切 gaokao.* 域名）在入库时直接丢弃——用户已是大二在读，这两类对他没有用。
- 模型每批 5 条整理：分类标签（报名/考试科目/专业对照/招生简章/其他）、一句中文摘要、要点、与「信息安全技术应用」专业的关系 `relevance`、需要用户做什么 `actionNeeded`；结果同样按链接持久化（`jiangxi:enrich:v1`），模型不可用时用规则兜底分类。
- 适用年份只从原文文本里解析，不猜；每条标 `noticeKind`：2028 年且官方来源为「2028 届正式通知」，往年为「往年备考参考」，其余为「尚待确认的动态」。2028 年四件事（报名通知/考试科目/专业对照表/招生简章）没有 2028 年条目覆盖时，页面显示「待公布」。
- 官方判定只看条目自身链接域名（jxeea.cn / .gov.cn / .edu.cn），媒体转载标「转载」，不冒充官方来源。

## 6. 海外机会整理（`loadOverseas`，用到模型）

- 候选来自 8 条通用搜索 + 8 条分国签证搜索 + 4 条岗位搜索（2026-11-22 新增：信息安全/网络运维/IT 技术支持的实习与岗位，Bing News RSS，窗口 150 天），MSN 转载先解析到原发布方。
- 入库前先丢弃：同一事件的转述（D/S 裁决、新西兰毕业后工签、英国毕业生签证缩短、日本语言学校新规、韩国技术试点各有专门匹配器）、面向其他地区人群的条目（如英国学生签证资金要求里针对非洲申请人的那条）、意见/评论类且超过 45 天的旧文（另有两篇点名删除的 2026 年 8 月评论）。
- 模型每批 3 条、逐批顺序执行，失败拆半重试到单条：判定是否保留（只留会改变决策的：专科可申请的新开项目、学分互认变化、奖学金开放、学生签证变化、留学生安全提醒；广告和论坛帖丢弃）、国家、变了什么 `whatChanged`、适用于谁 `whoApplies`、何时生效 `effectiveWhen`（没写明为 null，页面显示「未公布」）、适用学历三态 `eligibility`、是否移民类及适用身份 `identityLabel`、中文要点、是否签证类 `visa`，以及 2026-11-22 五类结构新增的 `category`（study 海外升学 / work_visa 海外实习、工作与签证）和 `stage`（prepare 在读可准备 / diploma 专科毕业可申请 / bachelor 本科毕业可申请 / intern 在读实习 / direct 专科毕业后从中国直接求职 / overseas_job 海外留学期间及毕业后就业 / general）。
- 没有 RSS 摘要的条目先尝试取文章页 meta 描述；仍没有就保持仅有标题。未整理成功的条目不会拿英文摘要冒充中文「变了什么」；这类条目的「和我有什么关系」目前多为通用句，深度整理依赖刷新时模型是否超时。
- **2026-11-22 新增：适用性优先于置顶（`isNotApplicableToUser`）。** eligibility 为 bachelor_only，或条目文本写明「不适用于我 / 不含信息安全技术应用」的，先移出首页、永不置顶，再谈固定区。人工条目里的新西兰毕业后工签、英国毕业生签证、韩国试点因此不在首页固定区显示，固定区实际为耶鲁 D/S、新加坡 MOM、日本语言学校 3 条。
- **2026-11-22 新增：轮换列表按事件去重（`sameOverseasEvent`）。** 标题归一化相同即同事件；否则同国家 + 共享 2 位以上显著数字 + 标题相似度 ≥0.6 + 7 天内才合并。印度–新西兰自贸协定有具名匹配器（`isIndiaNzFtaEventText`），标题没有显著数字也能合并，只留官方/最新一条。
- 签证类发现经 `mergePinnedVisaItems` 固定进「签证新政 · 固定区」，规则见 `config/columns.json` 的 `pinnedVisaNote`。

## 7. 首页「近期可申请」（`getDailyDigest`，不用模型）

2026-11-22 新增的纯规则合并接口，没有自己的缓存，实时读海外和学习两栏的已缓存结果：海外条目须是岗位、或有明确申请截止日期、或来源确认专科可申请，且不是 bachelor_only、不是政策（政策永不算可申请）、有可用入口、未被「中国境内打不开」屏蔽；学习条目须 needsApplication + 已确认 officialUrl + 截止日期未过。按标题去重后排序（官方优先 > 有截止日期 > 最新），最多 5 条；一条都没有时返回空数组，首页显示「暂无符合条件的新机会」，不拿别的凑数。

## 迁到自有环境时要替换的模型调用

| Muse 里的写法 | 自有环境替换为 |
| --- | --- |
| `ctx.inference.complete(prompt, { schema, timeout_secs })` | 你选的大模型 API，要求返回符合同一份 JSON Schema 的结构化结果 |
| Zod 的 `learningEnrichSchema` / `jiangxiEnrichSchema` / `overseasEnrichSchema` / 详情的 `{ introZh, points }` schema | 可直接复用为 JSON Schema 传给模型，或保留 Zod 做返回校验 |

模型只需要做翻译提炼和分类，不需要联网，也不需要很大的模型；关键是提示词里的「只依据摘要、不猜正文」约束要原样保留。
